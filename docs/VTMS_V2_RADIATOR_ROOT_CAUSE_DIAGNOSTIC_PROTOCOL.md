# VTMS-V2 Radiator Root-Cause Diagnostic Protocol

## Gate

`VTMS-V2-RAD-D0`

This protocol is frozen before executing the radiator-focused residual analysis introduced by External Review Intervention A2.

## Question

> After retaining the corrected V2 airflow boundary, is temperature residual structure materially associated with the modeled radiator heat-rejection regime on the two already-consumed Argonne runs whose constant external-fan boundary is documented?

The analysis cannot identify a new radiator law, estimate a Ford-specific heat-exchanger property, reopen validation, or authorize a blind prediction.

## Why this gate is necessary

VTMS-V1 uses an effectiveness-NTU radiator with effective UA independent of air or coolant mass flow except for the radiator-health multiplier. M0 corrected major control-boundary issues, but M0, M1, and M2 still inherit that radiator law.

An external staff engineering review identified constant UA as a plausible structural contributor to the observed cold bias. That criticism is physically interpretable but is not yet proven for the corrected V2 boundary. In particular, Argonne tests 71207062 and 71207063 are documented constant-speed external-fan, hood-up tests. Low dyno speed is therefore not evidence of low radiator-core airflow by itself.

The project tests residual localization before changing radiator physics.

## Residual convention

`residual = predicted ECT - measured ECT`

Negative residual means VTMS predicts coolant colder than measured.

## Required diagnostics

### Whole trace

For every evaluated run retain:

- bias
- MAE
- RMSE
- P90 absolute error
- bias fraction of MSE

### Measured-temperature regions

Use the frozen regions:

- below 80 C
- 80 to 88 C
- 88 to 92 C
- 92 to 96 C
- 96 to 100 C
- 100 to 130 C

The 88 to 92 C and 96 to 100 C regions are retained because prior consumed evidence showed comparatively small residual near the former and strong cold bias near the latter.

### Descriptive correlations

Compute residual correlation with:

- time
- measured ECT
- engine speed
- dyno speed, labelled only as an operating variable
- direct fuel-energy rate
- engine load
- measured oil temperature where available
- modeled thermostat fraction
- modeled radiator coolant flow
- modeled radiator air mass flow
- modeled radiator heat rejection
- modeled radiator effectiveness
- modeled radiator NTU

Pearson correlation is descriptive only and is not a causal score.

### Frozen binned summaries

Use the machine-manifest bins for:

- time
- modeled radiator air mass flow
- modeled radiator coolant flow
- modeled radiator heat rejection
- modeled thermostat fraction

Empty bins remain empty. They may not be merged after residual inspection.

## Required cross-run interpretation

A radiator model-form test is supported only if the complete primary diagnostic picture is consistent with a heat-rejection mechanism across both documented constant-fan runs and remains materially plausible across the two frozen `eta_pack` sensitivity snapshots.

Potentially supporting structure includes:

- residual magnitude varying systematically with modeled heat-rejection regime
- strongest cold bias occurring where the inherited constant-UA formulation implies disproportionate rejection
- temperature-region and heat-rejection-region diagnostics pointing in the same direction
- a radiator-specific relation remaining visible after engine/load/heat-input variables are inspected

The following do **not** by themselves support the hypothesis:

- correlation with dyno speed in a constant-fan test
- one large Pearson coefficient
- one run improving under a post-hoc radiator change
- a result dependent on relabelling external-fan capacity as measured core flow
- a supplementary 71207052/71207057 result whose airflow boundary remains unresolved

## Airflow language rules

For 71207062 and 71207063:

- boundary class is `CONSTANT_SPEED_EXTERNAL_FAN`
- protocol fan capacity is not measured radiator-core flow
- effective core-airflow transfer remains an engineering boundary assumption
- dyno speed must not be substituted for core airflow

For 71207052 and 71207057, unresolved cooling setup remains explicit unless stronger evidence is independently added.

## Data-rights rule

Raw Argonne rows and row-level reconstructed traces are not committed.

Detailed plots may be generated locally for engineering inspection, but public measured-trace plots remain blocked until a separate data-rights review determines what derived visualization may be redistributed.

Commit-safe outputs are limited to source hashes, aggregate statistics, frozen bin summaries, and other derived quantities that do not reproduce the raw dataset row by row.

## Outcome classes

### `RADIATOR_HYPOTHESIS_SUPPORTED_FOR_MODEL_FORM_TEST`

The complete primary residual structure is sufficiently consistent with radiator heat-rejection regime to justify freezing a physically sourced variable-UA candidate and bounds in RAD-P0.

This does not mean variable UA is proven correct.

### `RADIATOR_HYPOTHESIS_INCONCLUSIVE`

The radiator mechanism remains materially plausible but is materially confounded by boundary/control uncertainty. RAD-P0 may proceed only with those confounders explicitly carried forward.

### `RADIATOR_HYPOTHESIS_NOT_SUPPORTED`

The preregistered primary diagnostics do not show a consistent radiator-specific signature. The variable-UA intervention stops, the negative finding is preserved, and the previously frozen M2 Stage B path resumes unchanged.

## Prohibited actions during RAD-D0/D1

- parameter fitting
- optimizer execution
- parameter ranking
- residual-driven range widening
- opening blind evidence
- adding thermostat dynamics
- changing M2 acceptance criteria
- declaring a radiator cause from one diagnostic or one run

## Next gate

If supported or inconclusive, proceed to `VTMS-V2-RAD-P0`, where literature/provenance, candidate equation, reference flows, zero-flow treatment, and all parameter bounds are frozen before new physical-model execution.
