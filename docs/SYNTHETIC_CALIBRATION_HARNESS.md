# VTMS Synthetic Bounded-Calibration Harness

## Purpose

This harness verifies the software mechanics of the future controlled calibration workflow without using physical validation data.

It exercises the full sequence:

1. Generate deterministic synthetic observations from a known VTMS-V1 parameter set.
2. Freeze a calibration manifest and baseline parameter snapshot.
3. Fit only the manifest-authorized calibration parameters.
4. Enforce explicit lower and upper bounds.
5. Freeze the fitted parameter snapshot.
6. Generate a separate synthetic holdout case that was not used by the optimizer.
7. Run the frozen fitted parameter set on that holdout.
8. Evaluate the holdout with the same project acceptance thresholds intended for controlled physical validation.

## Critical limitation

Synthetic success is **not physical validation**.

The synthetic observations are generated by VTMS-V1 itself. Passing the synthetic holdout therefore proves that the optimizer, manifest locks, parameter freezing, result comparison, and acceptance evaluator work together as intended. It does not prove that VTMS-V1 represents a real vehicle accurately, that its model topology is sufficient, or that the selected uncertain parameters are identifiable from real Argonne data.

The test-only bounds returned by `synthetic_demo_bounds()` are deliberately scoped to this software exercise. They are **not approved Argonne calibration bounds and must not be reused for the real fit**.

## Fitted parameter subset

The harness uses the already-preregistered four-parameter subset:

- `wall_heat_fraction`
- `engine_thermal_capacitance_j_per_k`
- `engine_coolant_ua_w_per_k`
- `radiator_ua_nominal_w_per_k`

`run_bounded_calibration()` refuses to fit any parameter that is not declared by the calibration manifest, and `CalibrationBounds` must exactly match the manifest-declared fit set.

## Acceptance evaluator

The evaluator applies the project thresholds recorded in `AcceptanceCriteria`:

- RMSE <= 5 degC
- MAE <= 4 degC
- absolute mean bias <= 3 degC
- P90 absolute error <= 7 degC
- 60/80/90 degC arrival-time error <= the larger of 60 seconds or 10 percent of the measured arrival time

If a measured trace never reaches one of the temperature thresholds, that timing check is recorded as `not_evaluable` rather than silently treated as a pass or failure. If the measured trace reaches a threshold but the prediction never does, that check fails.

A calibration or challenge run can numerically satisfy every threshold, but it still cannot produce a formal validation-pass claim. `formal_validation_pass` can only be true when all three conditions are met:

1. the manifest role is `holdout`,
2. every applicable project threshold passes, and
3. the manifest explicitly sets `physical_evidence=true`.

`physical_evidence` defaults to `false`. This is a fail-safe so synthetic, generated, or otherwise non-physical evidence cannot become a validation claim simply because it was labeled as a holdout. The synthetic harness therefore expects its holdout to pass the numeric thresholds while `formal_validation_pass` remains false.

## Running the harness

```text
python run_synthetic_calibration.py
```

The script prints a JSON record containing:

- optimizer status and function-evaluation count
- initial and final least-squares cost
- each fitted value and its explicit bounds
- pre-fit and post-fit parameter snapshot hashes
- calibration metrics
- synthetic holdout metrics
- acceptance decisions for every project threshold
- the synthetic-only disclaimer

## Relationship to Argonne D3

When Argonne D3 data arrive, this harness is not converted into evidence. Instead, the controlled workflow will replace the synthetic generator with qualified measured data while preserving the same governance concepts:

- exact source-file hash
- declared calibration or holdout role
- reviewed signal mapping
- explicit confirmation that the qualified source is physical evidence
- explicit physical calibration bounds established before fitting
- frozen post-calibration parameter snapshot
- untouched holdout execution
- published acceptance evaluation and residuals

Real calibration bounds remain intentionally unresolved until they can be justified and preregistered independently of observed fit residuals.
